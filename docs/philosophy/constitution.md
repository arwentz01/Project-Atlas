# Atlas Constitution

## Purpose

Atlas exists to help clinicians turn reliable information into safe, practical action inside a complicated healthcare system.

## Principles

1. **No patient data by default.** Atlas is not a patient chart and should not invite storage of PHI.
2. **Every clinical or operational claim must be traceable.** Sources, versions, review dates, and ownership must be visible.
3. **Verified guidance, organization policy, and community experience are different things.** The interface must never blur them together.
4. **Evidence is versioned, never silently overwritten.** Historical versions remain attributable and auditable.
5. **Organizations own their local content and branding.** Shared contributions require an explicit choice.
6. **Context over navigation.** Atlas should infer a user's organization and task context whenever safe to do so.
7. **Search is a primary workflow.** Clinicians should reach useful information in seconds.
8. **HTML is the canonical format for printable resources.** PDF is an output, not the source of truth.
9. **Everything important is accessible through an API.** Interfaces must not be trapped inside one WordPress screen.
10. **Modules remain replaceable.** Search, rendering, document processing, and notifications must be abstracted behind interfaces.
11. **WordPress is infrastructure, not the product identity.** Atlas should feel like purpose-built clinical operations software.
12. **Clinical safety outranks convenience.** When speed and certainty conflict, Atlas must communicate uncertainty rather than imply confidence.
13. **The simplest safe implementation wins.** Complexity must earn its place.
14. **No feature exists without a user and a problem.** Feature proposals must state both clearly.

## Amendment Rule

Changes to this document require an explicit decision record describing the reason, impact, and tradeoffs.
