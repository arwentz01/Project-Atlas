# Open Questions

## Product and audience

1. Which user group should be the primary launch audience: individual nurses, outpatient practices, case management teams, or a mixed audience?
2. Which clinical setting should shape the first workflows?
3. Should Atlas initially be invitation-only while the content and trust model mature?
4. Which features will be free, professional, and organization-level?
5. What final brand personality should replace the Atlas codename?

## Initial content pilot

1. Which durable medical equipment categories create the most repeated frustration?
2. Which payers and geographic markets should be included first?
3. Which patient handouts and logs would deliver the most immediate value?
4. Who will serve as qualified reviewers for payer, clinical-skills, and laboratory content?
5. What source licenses or permissions are required for imported content, diagrams, and derivative materials?

## Editorial governance

1. What credentials are required for each reviewer role?
2. Will Atlas employ reviewers, contract with them, or use an expert contributor model?
3. What review interval applies to each content class?
4. What events cause immediate re-review?
5. How should conflicting reviewer opinions be resolved?
6. What wording and prominence should safety notices receive?

## Organizations and sharing

1. Can organization managers publish resources to a regional community, or only submit them for moderation?
2. Which organization customizations are controlled fields versus unrestricted editing?
3. How should ownership work when a staff member leaves an organization?
4. Can a user belong to multiple organizations?
5. How should regional communities be defined and governed?

## Referral and insurance participation data

1. Which public datasets and insurer directories permit reuse?
2. How often can each source be refreshed?
3. What constitutes verification?
4. How long should an unverified insurance-participation claim remain visible?
5. How should Atlas communicate that directory participation does not guarantee current network status or coverage?
6. Can organizations share successful referral experience without exposing patient information?

## Automation and search

1. Which automated tasks are safe enough for the first release?
2. Should generated answers be limited to reviewed Atlas content?
3. What citation granularity is required for answer cards?
4. How should the system behave when sources conflict?
5. What confidence threshold triggers a refusal to summarize?
6. How will terminology, abbreviations, misspellings, and lay language be mapped?

## Technology

1. Which stack best aligns with the eventual development team?
2. Which search engine provides the right balance of structured filters, semantic retrieval, cost, and operational simplicity?
3. Which document formats must be supported initially?
4. How will scanned documents be handled?
5. Is server-side PDF rendering required in the first release?
6. Which cloud and deployment model best fits the likely organization customers?

## Privacy, legal, and commercial

1. What contractual language prohibits patient information submission?
2. What automated and manual controls should detect accidental patient information?
3. Which security framework should guide the initial control set?
4. What professional liability and content disclaimers are appropriate?
5. What insurance coverage will the business require?
6. At what point should a formal HIPAA applicability assessment be commissioned?
7. What is the process for content takedown, correction, and dispute?

## Suggested next design session

The next session should select:

1. primary launch persona
2. first operational content domain
3. first ten patient resources
4. editorial workflow and reviewer model
5. initial stack and deployment assumptions
6. high-level screen map

Those choices will support a concrete MVP product requirements document and implementation backlog.
